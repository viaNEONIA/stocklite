# StockLite AI開発・継続管理ルール

適用: このリポジトリ全体。作成日2026-10-18 JST。根拠はユーザー「開発プロジェクト管理移行指示書 v1.0」。

## 作業開始

1. README、SPEC、ARCHITECTURE、TEST_RESULTS、ROADMAPと、対象配下のAGENTSを読む。
2. `git status --short`、現在ブランチ、HEAD、remote、最新origin/mainを確認。未コミット変更を破棄しない。
3. 実際のBUILD・コード・起動ファイルを照合する。現在mainの入口は診断ページであり、在庫アプリと取り違えない。
4. 対象版、変更範囲、実機結果の根拠を定める。不明な環境・仕様はUNKNOWNとして残す。

## GitHub運用・変更権限

- GitHubを共有の正本とする。ただし未pushのローカル開発コミットは未移管として別記する。
- 最新mainから目的別ブランチを作り、コミットしてPRを作る。今回のブランチ名は`docs/project-baseline`。
- mainへの直接コミット、force push、無断マージは禁止。PR作成とマージは別操作。
- 文書整備依頼では文書・試験証拠だけを変更し、HTML/JS/CSS/manifest/SW/テストコードを修正しない。既知不具合を発見しても記録で止める。
- 機能変更は明示された依頼範囲で行う。今回の文書移行を根拠に実装を開始しない。

## 状態と試験

- IMPLEMENTED=コード上で実装確認。VERIFIED=対象版・環境・確認内容が特定された範囲で動作確認。
- PLANNED=仕様確定済み未実装。PROPOSED=未確定案。DEFECT=既知不具合。UNKNOWN=確認不能。
- 模擬試験の合格は実機の合格ではない。ユーザー報告、JSON実測、コード監査を区別し、TEST_RESULTSに版・コミット・日時・環境・確認者を残す。
- 既存テストを対象ソースのまま実行する。変更なしの文書作業で新しい実装テストを追加しない。
- iPhone Safari/PWA、Android Chrome、保存・再起動・権限・数量確定の実機回帰は別途必要。未実施を成功扱いしない。

## 保護・禁止事項

- IndexedDB `stocklite` / `state` / `data` の初期化・消去、無断スキーマ変更をしない。
- 本番試験の前にユーザー端末でJSONバックアップ。取得できなければ取得済みと記載しない。
- 別パスでは同一オリジンのDBを共有し得る。隔離試験は別オリジン。サイトデータ削除を更新手順にしない。
- 正常動作版の上書き、既存資料の大幅削除、他プロジェクト（うちストック等）の仕様混在をしない。
- 認証情報・在庫バックアップ・カメラ画像・コード文字列を診断ログとして追加しない。既存測定証拠はハッシュで追跡し書き換えない。

## 完了報告

対象版/コミット、変更理由、変更ファイル、実施した検証と未実施、既知不具合/不明点、ソース変更の有無、branch/commit/PR/merge状況を報告する。接続不能ならローカル成果物と未反映事項を明記する。
